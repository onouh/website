## Problem

Booking systems fail in the data layer: ad-hoc SQL string-built in UI code, permissions enforced by hiding buttons, and concurrent orders corrupting seat state. I wanted the opposite — integrity enforced by the database itself, with the application structurally unable to bypass it.

## Approach

I architected a 3NF SQL Server schema of 12 tables with strict primary/foreign key constraints and role-based access control. Every read and write funnels through modular stored procedures and scalar functions — zero ad-hoc SQL in the application layer. On top sits a layered C# .NET WinForms client covering the three transaction concerns: user authentication, secure payment flows, and concurrent order state management across the full booking lifecycle.

## Outcome

A desktop system with one governed data path: 12 tables in third normal form, zero ad-hoc queries, and booking flows that stay consistent under concurrency. The integrity rules live in the schema where they cannot be forgotten — not in UI hope.

## Stack

C#, .NET, SQL Server, WinForms, 3NF, RBAC, stored procedures.
