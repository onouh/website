## Problem

Operating systems courses often stop at diagrams: a scheduler sketch, a paging overview, and no code that actually faults. I wanted a kernel where every mechanism — scheduling, allocation, replacement — runs for real, so the trade-offs are things I've hit rather than memorized.

## Approach

I engineered the kernel in C as three cooperating subsystems. The CPU scheduler is a Multi-Level Feedback Queue with dynamic priority boosting and aging, so CPU-bound processes cannot starve I/O-bound ones across queues. The allocator is a dynamic kernel heap managing direct virtual-to-physical translation, frame allocation, and a hierarchical page-directory / page-table structure. Replacement is an Nth-Chance Clock algorithm tied to working-set tracking, page-file I/O, and robust page-fault handlers.

Because the three are decomposed by concern, each policy can be reasoned about — and swapped — independently of the others.

## Outcome

A working kernel path from admission through memory and I/O: three subsystems (scheduler, allocator, pager), a two-level page-table hierarchy, and an aging policy that guarantees zero starved processes. Every mechanism is inspectable in source — scheduling and paging decisions are things I can explain line-by-line, not recite from a slide.

## Stack

C, MLFQ scheduling, virtual memory, hierarchical page tables, Nth-Chance Clock, fault handling.
